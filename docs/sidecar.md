# The sidecar bundle: `hardlywatching-server`

A **self-contained build of the HardlyWatching backend**: one directory you can copy to
another Linux x86_64 machine and run with no system Python, no project `.venv`, no `pip`
install and no checkout of this repo. It serves the same UI and the same `/api/*` routes as
`python3 server.py`, from the same code in this tree.

Built and measured on this workstation on 2026-10-23 (branch `task/m2-sidecar`):

| | |
|---|---|
| bundle | `dist/sidecar/` |
| size | **113 MB** on disk (`du -sh`), 117,544,408 bytes (`du -sb`), 110 files |
| build time | ~36 s with `.venv-build` present (that venv adds 93 MB, is not part of the bundle and is git-ignored) |
| CPython inside | 3.14.7 |
| works on | Linux x86_64 with **glibc ≥ 2.38** (Fedora 39+, Ubuntu 24.04+, Debian 13+) |

---

## Build it

```bash
bash packaging/sidecar/build.sh
```

That one command:

1. creates `.venv-build/` with `/usr/bin/python3 -m venv` (a **build-only** venv; the app's
   `.venv` is never used or touched),
2. installs `pyinstaller`, `Pillow` and `pillow-heif` into it — only when missing, so a
   second run does no network work,
3. runs PyInstaller with `packaging/sidecar/hardlywatching.spec` → `dist/sidecar/`,
4. copies the external tools into `dist/sidecar/bin/` and writes
   `dist/sidecar/bin/PROVENANCE.txt` (source path, version, sha256 for each),
5. prints the layout and the size.

`set -euo pipefail`, idempotent, and it never reads or writes `~/.config/hardlywatching`,
`~/instagram` or the running service on `127.0.0.1:8765`.

Nothing built here is committed: `.venv-build/` and `dist/sidecar/` are in `.gitignore`.

Environment knobs for the build: `PYTHON=/path/to/python3`, `YTDLP_BIN=`, `FFMPEG_BIN=`,
`FFPROBE_BIN=`.

## What is in it

```
dist/sidecar/
├── hardlywatching-server          3.0 MB   the exe (PyInstaller bootloader + entry.py)
├── _internal/                      71 MB   CPython 3.14.7, stdlib, Pillow, pillow-heif,
│                                            web assets (index.html, shorts.html, manifests,
│                                            icons), LICENSE
└── bin/                            39 MB   yt-dlp 38.0 MB, ffmpeg 430 KB, ffprobe 198 KB,
                                             PROVENANCE.txt
```

`_internal/` is PyInstaller 6's standard onedir payload; `hardlywatching-server` is the only
exe. Largest single items: `bin/yt-dlp` 38.0 MB, `pillow_heif.libs/libx265` 21.8 MB,
`libpython3.14.so.1.0` 6.3 MB, `libcrypto.so.3` 5.5 MB, `PIL/_imaging...so` 3.3 MB.

Python packages inside (versions from the build venv): **Pillow 13.0.0**, **pillow-heif 1.8.1**,
**PyInstaller 6.22.3**. `sqlite3`, `ssl`, `bz2`, `lzma`, `zstd` and `uuid` ship as bundled
shared libraries in `_internal/`, so none of them come from the host.

### Where the bundled tools came from

`dist/sidecar/bin/PROVENANCE.txt` is regenerated by each build; this is the current one:

| tool | copy taken from | version | note |
|---|---|---|---|
| `yt-dlp` | `/home/bazzite/Shutter Encoder/Library/yt-dlp_linux` | 2026.06.09 | the official **standalone** yt-dlp build (carries its own Python). Copied, not downloaded. |
| `ffmpeg` | `/usr/bin/ffmpeg` | 8.1.3 | the host's binary — **dynamically linked**, see the limits below |
| `ffprobe` | `/usr/bin/ffprobe` | 8.1.3 | same |

The pipx `yt-dlp` on `PATH` (`~/.local/bin/yt-dlp`, 2026.08.19) was deliberately **not** used:
it is a console script whose shebang points at
`~/.local/share/pipx/venvs/yt-dlp/bin/python`, i.e. useless on any other machine.
`build.sh` checks each candidate is a real ELF executable and skips scripts.

## How the frozen process still finds its own files

Three things in `packaging/sidecar/entry.py` make an unmodified `server.py` work frozen:

1. **Web assets.** `server.py` computes `HERE = Path(__file__).resolve().parent` and serves
   `index.html`, `shorts.html`, the two webmanifests and the icons out of it. In a PyInstaller
   onedir bundle a frozen module's `__file__` is `<bundle>/_internal/server.py`, so `HERE`
   *is* `sys._MEIPASS` — and the spec's `datas` puts exactly those files there (dest `"."`).
   Verified, not assumed: `--self-check` prints

   ```
   server.__file__ : .../dist/sidecar/_internal/server.py
   server.HERE     : .../dist/sidecar/_internal
   HERE == _MEIPASS: True
     asset index.html                   ok
   ```

   So **no change to `server.py` was needed.** As a safety net for other layouts, `entry.py`
   checks `server.HERE` for `index.html`/`shorts.html` and, only if they are missing, assigns
   the module attribute `server.HERE = <dir that has them>` (runtime attribute, never a source
   edit) and says so on stderr. That fallback did not trigger in any build here.

2. **`PATH`.** `engine.py` calls `yt-dlp`, `ffmpeg` and `ffprobe` by bare name. `entry.py`
   puts `<bundle>/bin` first on `PATH` before importing `server`, so the bundled copies win
   over anything installed on the host. Proof: with `PATH=/nonexistent`, `--self-check` still
   reports `tool yt-dlp .../dist/sidecar/bin/yt-dlp`.

3. **`argv`/env.** `server.py` parses `--port`/`--host` and the `INSTA_*` variables *at import
   time*. `entry.py` therefore never removes anything from `sys.argv`; it only reads it. It
   also mirrors `--port`/`--host` into `INSTA_PORT`/`INSTA_HOST` for good measure.

Extra flags `entry.py` adds on top of the app's own:

| flag | effect |
|---|---|
| `--no-browser` | never open a tab (also `INSTA_NO_BROWSER=1`). Replaces `server.webbrowser` with a no-op for the life of the process; the app's source is untouched. |
| `--self-check` | print the resolved asset dir, tool paths, Pillow versions, port and output root; exit 0/1. Serves nothing. |
| `--version` | `hardlywatching-server 0.1.0 (frozen, CPython 3.14.7)` |
| `-h`, `--help` | usage |

`SIGINT` (Ctrl-C) and `SIGTERM` both unwind `serve_forever()`; the process exits **0**, closes
its socket and leaves no child behind. If some future non-daemon thread outlived `main()`, the
interpreter is abandoned with `os._exit(0)` rather than left running — an orphan backend is
worse than a skipped teardown for the desktop shell that spawns it.

## Test it

Run the whole thing in a throwaway environment and a port that is not the live one (8765):

```bash
dist/sidecar/hardlywatching-server --self-check          # does everything resolve?
```

```bash
bash packaging/sidecar/build.sh            # build, prints: dist/sidecar 113M / 117544408 bytes
```

No-system-Python proof — empty environment, no project venv anywhere on `PATH`, temp `HOME`:

```bash
T=$(mktemp -d)
env -i PATH=/usr/bin:/bin HOME="$T" \
    INSTA_STATE="$T/state.json" INSTA_CACHE_DB="$T/c.db" INSTA_OUTPUT="$T/ig" \
    INSTA_PORT=8901 BROWSER=/bin/echo \
```

  on a PNG → `200 image/jpeg 8245B` (bundled **Pillow**),

Process and shutdown checks:

```bash
PID=$(for p in /proc/[0-9]*; do
        case "$(readlink "$p/exe" 2>/dev/null)" in
          *dist/sidecar/hardlywatching-server) echo "${p#/proc/}";; esac; done)
pstree -p "$PID"                 # hardlywatching-(3983145)   -- one process, no python
grep -E '\.venv|site-packages' /proc/$PID/maps || echo 'none'
kill -INT "$PID"                 # rc=0, "stopped.", socket closed
```

Used here: `pstree -p` **and** the `env -i` invocation, plus `/proc/<pid>/maps` grepped for
`.venv`/`site-packages`/the apps checkout — no match. `libpython3.14.so.1.0` mapped by the
process comes from `<bundle>/_internal/`, not from any interpreter on the machine.

After `kill -INT`: exit code **0**, `stopped.` on stdout, port 8901 closed, and a scan of
every `/proc/*/exe` for the bundle's path found **no orphan**. (`pgrep -fa hardlywatching-server`
is a bad check here: it matches your own shell's command line. Scan `exe` links instead.)

## What it does not contain, and what will break

Honest list, worst first.

1. **ffmpeg is the weak link.** `bin/ffmpeg` and `bin/ffprobe` are the *host's* binaries, and
   they are dynamically linked:

   ```
   libavdevice.so.62 libavfilter.so.11 libavformat.so.62 libavcodec.so.62
   libswresample.so.6 libswscale.so.9 libavutil.so.60
   ```

   Those seven `.so` files must exist on the target machine, with **those exact sonames**
   (FFmpeg 8.x, as shipped by Fedora 43/44). On a machine with no FFmpeg, or an older one
   (Ubuntu 24.04 ships 6.x), the copied binary fails with
   `error while loading shared libraries: libavcodec.so.62` — which breaks **video
   thumbnails, hover previews and `make_playable` transcoding**. Images still thumbnail
   (Pillow is fully bundled) and the UI still loads. Bundling FFmpeg's whole shared-library
   closure is not a small fix: on this machine it is **320 libraries / 256 MB**, most of it
   encoders the app never uses. The right fix is a static or trimmed FFmpeg build (BtbN
   `ffmpeg-master-latest-linux64-gpl`, `--disable-everything` plus h264/hevc/vp9 decode +
   mjpeg/png encode) fetched by CI, not from this box.

   Because `bin/` is *prepended* to `PATH`, a broken bundled ffmpeg shadows a working host
   one. Escape hatch: delete `dist/sidecar/bin/ffmpeg` (and `ffprobe`) and the app falls back
   to whatever `ffmpeg` the host has.

2. **instaloader is not bundled.** The app is a front end for it, and it is a Python package,
   so the bundle cannot carry it as a file the way it carries `yt-dlp`. Started without one it
   prints the "instaloader is not installed" block and the UI still serves, but **nothing
   Instagram-side will download**. The app offers `pipx install instaloader` on first run
   (interactive only; a sidecar spawned by the desktop shell is not a TTY and just prints the
   instructions). Bundling it means a second PyInstaller exe in the same COLLECT — the obvious
   next task, not done here.

3. **Linux x86_64 only.** The bundle embeds CPython 3.14.7 and glibc symbol versions up to
   **GLIBC_2.38**; it will not start on Ubuntu 22.04 (2.35) or any rpm/deb older than
   Fedora 39 / Debian 13. `ffmpeg` raises the same floor. Fix: build in an older container.

4. **Windows and macOS need their own build on their own runner.** PyInstaller does not
   cross-compile: the exe and every `.so` inside are Linux ELF. Porting means running this
   same spec on `windows-latest` / `macos-latest`, with `yt-dlp.exe` / `yt-dlp_macos` and
   `ffmpeg.exe` / `ffmpeg` for that platform, different `bin` names, and macOS signing +
   notarisation before Gatekeeper will open it. `_MEIPASS` behaves the same on all three, so
   `entry.py` and the spec need no restructuring.

5. **No single-instance protection in this bundle.** The M1 lock lands in `server.py`
   (`hwa/m1-lock`); until it merges, a second sidecar silently binds 8766 against the same
   state (see plan §0). The desktop shell must not spawn twice.

6. **Not signed, no auto-update, no installer.** It is a directory. Version it with
   `--version` (currently `0.1.0`) and put a real DEB/AppImage around it.

7. **Size.** 113 MB, of which 38 MB is yt-dlp and 22 MB is the libx265 that pillow-heif pulls
   in for HEIC. `pillow-heif` is optional at runtime: dropping it from the spec saves ~25 MB
   and only costs HEIC thumbnails.

8. Nothing here is published. `dist/` is ignored by git and stays local.
